# Domain docs

Forge3D uses a single domain context.

## Before exploring

Read these sources when they exist and apply to the work:

- `CONTEXT.md` for the project glossary and current domain model.
- ADRs under `docs/adr/` for decisions affecting the area being changed.

Proceed when either location is absent. The domain-modeling workflow creates a glossary or ADR when a real terminology gap or durable decision calls for one.

## Vocabulary

Use terms as `CONTEXT.md` defines them in issues, plans, code, tests, and reviews. If a needed concept is missing, check whether existing project language already covers it before adding a term.

Surface conflicts with an ADR. Do not silently replace an accepted decision.
